# PageFold Fork

PageFold(Risu 플러그인)의 개인 포크입니다. 원본 플러그인은 원 개발자의 것이며, 이 저장소에는 원본 파일과 포크 변경만 들어 있습니다.

## 포크 변경 사항

- 플러그인 ID `pagefold-fork`, 표시 이름 `PageFold Fork`, 버전 `원본 버전.N` (예: `0.2.7.10`)
- 원본과 겹치는 것이 없음: 저장 키 `pagefold-fork.*`, 등록 모델 ID `pagefold-fork-…`, Risu에 보이는 모델 이름에 Fork 표시, 설정 메뉴·설정 화면 제목 `PageFold Fork`(PFF), 알림·스타일 DOM 이름, 글꼴 캐시 키
- 포크에 설정이 하나도 없을 때(첫 실행)만 원본 PageFold 설정을 한 번 복사해 옴
- `PDF 변환 방식` → `파일 변환 방식`, 선택지 `PDF 텍스트` / `PDF 이미지` / `PNG 이미지`
- `PNG 이미지`: PDF 이미지와 같은 방식(흰 바탕·검은 글씨, 한 페이지에 다 안 들어가면 여러 장)으로 그리되, 페이지마다 PNG 이미지로 보냄. 이때 OpenRouter 요청에서 `file-parser` 플러그인을 넣지 않음
- 모델 ID에 `gemini`, `gpt`, `claude`가 없으면 `PNG 이미지`만 선택 가능
- PDF 이미지·PNG 이미지의 `해상도`(자동/낮음/중간/높음): 그리는 픽셀 밀도(1·1.5·2배, 자동 2배)와 모델 읽기 해상도(Gemini media resolution, 게이트웨이 PNG는 `detail`)를 함께 정함. 자동은 원본 동작 그대로
- 요청 예상 토큰을 이미지 모드·해상도·모델별로 계산 (Gemini 280/560/1120, 게이트웨이 PDF 이미지 560, 그 외 모델은 픽셀 수 기준)
- 통계 화면 `마지막 이미지 보기`: PDF 이미지·PNG 이미지 방식으로 마지막에 보낸 페이지 그림을 화면에 보여주고 PNG·PDF로 내려받게 함 (이번 세션 요청은 메모리에서, 그 밖에는 요청 로그에서 다시 그림. 요청 로그에 그리기 설정과 문서별 원문을 함께 저장하며, 그 이전 로그는 원문을 지금 프로필 설정으로 다시 그림)
- 통계 화면 `OCR 검사`: 그 페이지 중 N장(처음·중간·끝 고르게)을 같은 모델에 받아쓰기시켜 페이지별 글자 오류율(공백·줄바꿈 제외 편집 거리)과 틀린 줄을 보여줌. 시작 전 예상 토큰·비용 확인. 페이지당 180초 제한, 중단 버튼, 출력 상한은 원문 길이 기준
- `지금 설정으로`(기본 켜짐): 마지막 요청(이번 세션 메모리 또는 요청 로그)에서는 원문만 가져오고, 방식·글자 크기·해상도·프로바이더 설정은 지금 프로필 값으로 다시 그림. 끄면 보냈을 때의 설정으로 그림
- 요청 로그 탭 `PDF 내용` → `파일 본문`
- PNG 모드에도 쓰이는 UI 문구의 PDF → 파일/이미지 (표시 없이 문구만 바뀜, 재적용 시 아래 목록 참고): `공통 PDF 설정`→`공통 설정`, `텍스트 PDF 글자 크기`→`PDF 텍스트 글자 크기`, `이미지 PDF 글자 크기`→`이미지 글자 크기`, 역할 병합·패키징 도움말, 통계 `생성 PDF 페이지`→`생성 페이지`·열 `PDF`→`파일`, 요청 알림 `PDF Np`→`파일 Np`, 진행 단계와 이미지 렌더링 오류 메시지

## 구조

- `upstream` 브랜치: 원본 파일 그대로
- `main` 브랜치: `upstream` 위에 포크 커밋. 포크 파일 이름은 버전과 상관없이 `pagefold-fork.js`로 고정 (자동 업데이트 주소: `//@update-url https://raw.githubusercontent.com/nanigaarimasuka/page-fold-fork/main/pagefold-fork.js`)

포크 코드는 파일 맨 위 `// [PAGEFOLD FORK]` ~ `// [/PAGEFOLD FORK]` 블록에 모여 있고, 원본 코드는 `/* PAGEFOLD FORK */` 표시가 붙은 줄에서만 그 블록을 부릅니다. 원본 `packagePrompt`는 `packagePromptUpstream`으로 이름만 바뀌고, 포크 블록의 `packagePrompt`가 이를 감쌉니다.

## 원본이 새 버전으로 나왔을 때

1. `upstream` 브랜치에 새 원본 파일을 커밋
2. `main`을 `upstream` 위로 rebase
3. 충돌이 나면 포크 블록은 그대로 두고, `/* PAGEFOLD FORK */` 표시 줄만 새 원본에 맞춰 다시 적용
